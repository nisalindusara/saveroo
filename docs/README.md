# Saveroo docs: index

Read `progress.md` first in every session. Then open only what the task needs.

| File | What it holds | Read when |
|---|---|---|
| `progress.md` | Current milestone, done, next, decisions log, open items | Start and end of every session |
| `product.md` | Vision, why it exists, principles, competitors, brand | Writing copy, naming, or making product trade-offs |
| `features.md` | Full feature list, each tagged with its release (R1-R5) | Deciding what is in or out of scope |
| `release-1.md` | Release 1 scope, non-goals, ordered milestones M0-M13 with "done when" tests | Starting or finishing any milestone |
| `architecture.md` | Tech stack and why, repo layout, conventions, performance budgets, security | Any technical decision |
| `data-model.md` | Every table, columns, relations, key logic (usable deals, next valid date) | Touching the database or writing queries |
| `screens.md` | Screens and user flows | Building any UI |
| `revenue-model.md` | Staged money model, premium rules, data policy | Anything involving ads, premium, partners or data |
| `location-and-alerts.md` | Shopping Mode, valid-day reminders, notification rules, location privacy | Notifications, reminders, location |
| `dev-setup-windows.md` | Setting up the owner's Windows machine and accounts | Environment problems or new accounts |
| `codemap.md` | Map of the codebase: folders, key modules, data flow | Before editing unfamiliar code |
| `specs/` | One short spec per feature, written just before it is built | Building that feature |

Release legend: R1 Launch (web + Android) · R2 Before you pay (extension, Shopping Mode, price tracking, premium, ads) · R3 Everyone (iOS, Sinhala/Tamil, WhatsApp, referrals) · R4 Merchants (portal, campaigns, receipts) · R5 Scale (ML, cashback, partnerships, insights).
